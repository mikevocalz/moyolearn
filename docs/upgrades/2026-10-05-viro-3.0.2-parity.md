# Viro 3.0.2 parity and upstream-next coverage

## Release baseline

Moyo moves from the stale `3.0.1-moyo.1` vendor tarball to a fresh
`3.0.2-moyo.1` vendor tarball built from the mikevocalz/viro fork — which
carries upstream 3.0.2 integrated (see `e14bdf5` there) plus the Moyo surface.

The original plan of this PR was npm `@reactvision/react-viro@3.0.2` plus a
small stylus patch. Typecheck disproved it: the published tarball has no
`ViroRivePanel`, no morph-target/skeleton APIs on `Viro3DObject`, no `isPico`,
and different `ViroSceneNavigator` props — the Moyo overlay is the whole fork
delta, not a patch. The vendored tarball remains the delivery vehicle; the
patch-package overlay shrinks to the single `moyoViroRendererAar` gradle hook.

ReactVision 3.0.2 is the current public release and bundles ViroCore 3.0.2. The 3.0.2 line already contains the merged renderer fixes from Viro #545–#550 and ViroCore #397–#399.

## Upstream-next (PR #87)

This branch steps the vendored package to `3.0.2-moyo.2`, packed from the
fork's `moyo/upstream-next-3.0.2` branch, which carries the three
post-3.0.2 upstream PRs integrated at the source — no patch fiction:

- Viro #555 — active camera mounted between siblings
  (`ViroActiveCameraTracker`, ARScene/Scene/VRTView/VRTCamera changes).
- Viro #556 — `VRTObjectDetectorView` ships in the iOS bridge again, with
  a `hasViewManagerConfig` degrade (`VIRO_OBJECT_DETECTOR_UNAVAILABLE_ERROR`)
  so a missing view reports a named error instead of taking the screen down.
- Viro #557 — Quest relaunch loop: the AppState auto-relaunch is removed and
  explicit re-entry goes through `renderQuestPanel`/`QuestPanel`; in-room
  scene HUD with Y-button menu; `StudioQuestText`; `questFeatures` and
  `questHorizonOsSdk` plugin options; HAND_TRACKING and BOUNDARY_VISIBILITY
  declarations; Java-side plane/launcher fixes in the rebuilt bridge AAR.

Merge decisions worth knowing (all in the fork commit `upstream-next: carry
ReactVision #555, #556, #557`):

- The fork already had its own relaunch-loop guard (AppState relaunch +
  `VRLauncher.vrDestroyed` listener). Upstream's model replaces auto-relaunch
  with explicit panel re-entry — the listener stays as defence-in-depth for
  the OS-kills-VRActivity path, the relaunch does not come back.
- PICO gets the same explicit re-entry panel as Quest; it does not keep a
  null-surface auto-relaunch path.
- Moyo plugin options (`metaVrGlassesCompatible`, `metaDefaultDeviceTargets`,
  `metaSpatialLayout`, `trackingOrigin`) coexist with upstream's
  `questFeatures`/`questHorizonOsSdk`.

## Native artifacts in this PR

Two binaries ship the parts a tarball patch could never carry:

- `vendors/reactvision-react-viro-3.0.2-moyo.2.tgz` — bundles the bridge AAR
  (`react_viro-release.aar`) rebuilt from the merged `viro_bridge` sources
  and the renderer AAR below.
- `vendors/viro-renderer-c09855d2.aar` — renderer rebuilt from
  `mikevocalz/virocore@c09855d2` (`Quest: hide the boundary while passthrough
  is on`, `Quest: hand a scene attached later the planes found so far`, plus
  the v3.0.2 Quest capture/hit-test/gaze merges), pinned by sha256 in
  `apps/mobile/android/build.gradle`. The pinned AAR and the tarball's
  bundled `viro_renderer-release.aar` are the same build — the pin is the
  integrity check, the bundle is the default.

## Deferred upstream work

- Viro #554 — function-region pinning. Deferred until its matching ViroCore #404 dependency is available and tested together.
- ViroCore #403 — Core Location starts only when a key/project is configured.
- ViroCore #404 — function-region propagation through cloud-anchor providers.
- ViroCore #405 — Quest plane replay.

These ViroCore changes affect prebuilt native renderer binaries. They should not be faked by changing TypeScript/package versions; they need a renderer rebuild and device validation.

## Acceptance gates

1. `pnpm install --frozen-lockfile` succeeds and patch-package applies cleanly.
2. `pnpm typecheck`, `pnpm lint`, and `pnpm test` remain green.
3. Android: assemble the phone, Quest, and Pico variants.
4. iOS: pod install and build the Viro bridge; exercise ObjectDetector and active-camera remount.
5. Quest: launch/relaunch, camera/input, hit-test, screenshot/recording, and drag regression.
6. visionOS: rebuild pods and run the spatial-stylus path, including disconnect/reconnect.
7. Only after native gates pass should the old vendored 3.0.1 tarball be deleted from `vendors/`.
