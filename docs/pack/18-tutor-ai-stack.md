# Tutor AI Stack — ADR-018: Claude primary · Gemini paired · ExecuTorch edge
**Doc 18 · Moyo platform pack · Status:** Accepted (routing evidence pending) · **Date:** Aug 21, 2026 · **Deciders:** Mike
**Context:** Three inputs collided and needed reconciling: (1) the standing decisions — Anthropic as the cloud brain, ExecuTorch on-device, the Anthropic-vs-Vertex-Gemini bake-off; (2) an advisor analysis proposing a TutorModelRouter with Gemini Live as the brain, React Native AI as provider façade, and ExecuTorch as the edge layer; (3) the newly emphasized requirement: **top-tier teaching quality across all subjects and all grade bands — elementary, junior high, high school.** This ADR resolves all three. Skills applied: engineering:architecture (this format), system-design (doc 12 continuity).

---

## 1. Decision
**Claude is the tutor brain. Gemini is paired — not competing — in lanes where it is complementary or unique. ExecuTorch is the edge nervous system. Callstack's react-native-ai is the provider façade where system models fit. Teaching quality is enforced by a subject×band eval registry that gates what ships, per cell, fail-closed.** The advisor doc's *shape* (router + façade + edge) is adopted; its brain assignment (Gemini Live) and parts of its model registry are corrected below.

## 2. The pairing (Anthropic + Gemini, resolved)

## 3. The education-quality system (the requirement that reshapes everything)
Model choice is necessary but not sufficient. "Top tier on all subjects, all grade levels" is a **system property**, built from five layers the model sits inside:
1. **The pedagogy contract** (system-owned, provider-independent): never reveal the answer; diagnose the misconception before correcting; recognize near-correct reasoning; shift strategy on repeated failure; maintain lesson state; use the learner's history. Encoded as the tutor-turn prompt frame + post-turn checks — the same contract every routed provider must satisfy, which is what makes routing safe.
2. **Curriculum grounding:** standards-aligned content RAG (Common Core / NGSS-mapped, per subject×band) from the edu store — the model teaches *our* curriculum sequence, not its priors. 2026's converging lesson: <cite-free>every major lab now ships a Socratic "learning mode"; differentiation lives in grounding and the student model, not the base behavior</cite-free>.
3. **Tool-first accuracy:** arithmetic and symbolic math run through a gateway code-execution tool — the model orchestrates, the tool computes; chemistry/physics numericals likewise. Verified-solution sets back curriculum problems.
4. **The student model:** the knowledge graph (doc 12 edu schema) supplies mastery state so scaffolding lands at the learner's actual frontier — the research consensus is that grade-appropriateness is a *designed* property (grade-specific behavior must be built and evaluated, not assumed from general capability).
5. **The gate: `tutorCapabilities[subject][band]`** in the registry. A cell ships only when its eval suite passes: pedagogy rubric (LearnLM-paper-style comparative rubric, our scenarios), subject-accuracy sets (elementary arithmetic → HS calculus/chem/physics/literature analysis), never-reveal probes, misconception-handling probes, band reading-level output checks (doc 08 bands), red-team. **Fail-closed per cell** — exactly the `aiTutorLocales` pattern extended to subjects. The eval harness is the bake-off, industrialized: it runs continuously, per provider, and *is* the routing table's source of truth.

## 4. ExecuTorch — the edge nervous system (verified against the real registry)
[react-native-executorch](https://github.com/software-mansion/react-native-executorch) (Software Mansion, New-Arch-only — starter ✓) is confirmed as the edge layer, and it's stronger than the advisor doc knew:
- **Whisper STT + VAD** with a [streaming VAD API and ~10× transcription perf via the VAD-integrated pipeline + NPU exports](https://github.com/software-mansion/react-native-executorch/releases); CoreML-backed Whisper default on iOS. **This closes doc 15's open Android-STT ADR:** Android voice input = ExecuTorch Whisper on-device — the child's raw voice never leaves the device on *either* platform. (iOS may still prefer Apple SpeechAnalyzer via react-native-ai; both satisfy the rule — pick per-platform at PR.)
- **Kokoro TTS, multilingual** ([model repo](https://huggingface.co/software-mansion/react-native-executorch-kokoro); releases note 🇪🇸🇫🇷🇮🇹🇵🇱🇮🇳 voices + phonemization improvements) — non-tutor TTS or system sounds. It is **not** the learner-facing Natalie voice; the tutor uses one pinned ElevenLabs voice on every path, with text-only degradation (doc 32).
- **Embeddings (CLIP-style image+text), OCR (+experimental vertical), YOLO/RF-DETR detection, SAM segmentation** ([docs](https://docs.swmansion.com/react-native-executorch/)) — homework-photo preprocessing (detect → OCR → redact → send text+crop to the brain) and doc-15's local retrieval lane.
- **LLM runtime with tool calling** (Hammer 2.1 / Qwen 3 families per the [current guides](https://reactnativerelay.com/article/react-native-on-device-ai-run-llms-locally-executorch-react-native-ai)), **background model downloads and built-in benchmarks** — the advisor doc's "Model Capability Manager" primitives already exist in the library.
- **Registry corrections (anti-slop):** verified today on [Software Mansion's HF org](https://huggingface.co/software-mansion): Llama 3.2 1B/3B, Qwen 2.5, Qwen 3 (incl. 0.6B), Phi-family, Hammer 2.1, Whisper (+Moonshine), Kokoro, embeddings, vision models. The advisor doc's "Qwen 3.5 / Gemma 4 / Phi-4 Mini / LFM" entries **did not appear in what I verified** — pin exact model constants against the installed library + HF org at the PR, never from any doc's memory (including this one).
- **Parked — sovereign on-prem agent kernels** (e.g. [NS-BOS Kernel](https://github.com/NGARiAI/ns-bos-kernel), Apache 2.0): Linux/Python kernels running local inference (Ollama/llama.cpp/vLLM) on owned hardware (Jetson Orin, Pi 5, x86_64) with hash-chained audit trails and kernel-level RBAC. **Not adoptable on any learner path** — a local model serving a child's tutoring turn is exactly what the prohibition below forbids, and owning the hardware supplies neither a Safety Plane, an eval-passed cell, nor incident-speed patching. The one lane worth revisiting is **district data-residency** (doc 25): a district contractually barring student data from leaving its infrastructure could host the OneRoster/Content-Connector sync worker and the LMS retrieval index on-prem while the tutor brain stays in the gateway. Reconsider only when (a) a signed district requires it, (b) the project shows real release history — as verified: ~12 commits, 1 star, no releases — and (c) the deployment model earns its own ADR. Useful now as *prior art*, not a dependency: read its `THREAT_MODEL.md` and hash-chained audit design against doc 07's audit requirements.
- **The prohibition stands, and the advisor doc agrees** ("I would NOT make the local model the actual tutor"): on-device generation never serves a learner tutoring turn — no Safety Plane, no audit, no incident-speed patching on device. Edge = senses (speech, vision, retrieval), never the brain.

## 5. Client integration
- **Provider façade:** [react-native-ai](https://www.react-native-ai.dev/docs) (Callstack) where system models fit (Apple FM/SpeechAnalyzer per doc 15) + AI SDK compatibility; **build `@moyo/ai-provider-executorch`** — an AI-SDK-style provider over ExecuTorch (none documented upstream; ours to write) so the app has one model API while the router decides.
- **TutorAI application layer** (advisor shape adopted): `conversation / speech / perception / memory / pedagogy / tools / modelRouter` — React components never know which lane answered. Lives in `packages/app/features/tutor`; identity never a parameter (doc 11).
- **Capability manager:** device probe (system-model availability, RAM class, storage, battery/thermal) → download only what this device's plan needs via ExecuTorch's background downloads + checksums; zero bundled weights; per-device manifests logged for support.

## 6. Consequences & trade-offs
Easier: best-model-per-cell without lock-in; realtime voice unlocked without abandoning the Anthropic center; Android voice solved on-device; a defensible "why is Natalie good at teaching" answer (the eval registry) for parents, districts, and procurement. Harder: two provider relationships (mitigated by the Vertex option), an eval harness that must exist *before* routing claims mean anything (it's PR-50, deliberately early), per-cell cost/latency accounting in the doc-12 budget. Revisit triggers: a provider ships a pedagogy-tuned tier that sweeps our cells; realtime-voice demand arrives before Phase 3; ExecuTorch adds a model that changes the edge calculus.
