# Native AI Client Spec — the Margelo/Callstack stack, integrated properly
**Doc 15 · Moyo platform pack · Date:** Aug 20, 2026
**Sources (read in full, Aug 20):** Margelo's "Building a ChatGPT-Style AI Chat App in React Native with RAG & Streaming" (Dave Mkpa-Eke, Jul 2026) + the `margelo/ai-chat-demo` source it opens, and **Callstack's** `react-native-ai` docs (`callstackincubator/ai` — attribution matters: the package is Callstack's, the demo/blog are Margelo's; both are roster-tier RN shops).
**The governing resolution — three lanes, stated up front:**
1. **ADOPT — the chat client architecture and perf discipline.** Everything about how the chat *feels* — pointed at **our** inference gateway instead of a provider.
2. **ADOPT — on-device speech (STT first).** The child's raw voice never leaves the device; only the transcript enters the Safety Plane. A privacy *upgrade* to doc 07, not an exception.
3. **PROHIBIT — on-device generation on any learner tutoring path.** Doc 07's ten layers, audit, and fail-closed rule live server-side; an on-device model has none of them and can't be patched at incident speed. This is binding and not revisited by feature pressure. (Their own blog agrees on the adjacent point: never ship a provider key in a bundle — a real product puts a backend between the app and the model. Ours is the gateway.)

## 1. The chat client architecture (Natalie's surface, Wave 2 UI → Wave 5 live)
Adopted from the demo, re-pointed at the doc-12 gateway (SSE, screened stream):
- **List mechanics: [LegendList v3](https://github.com/LegendApp/legend-list)** ([API](https://www.legendapp.com/open-source/list/v3/api/) · [performance guide](https://www.legendapp.com/open-source/list/v3/performance/)) — `anchoredEndSpace` (the just-sent message rides to the top and holds while the reply streams below — the ChatGPT scroll pattern), `scrollMessageToEnd`, `KeyboardAwareLegendList`, follow-the-bottom once the anchor space closes. Tune per its performance guide (`recycleItems`, `estimatedItemSize`, stable keys, `drawDistance`).
- **Keyboard: [react-native-keyboard-controller](https://kirillzyusko.github.io/react-native-keyboard-controller/)** ([KeyboardStickyView](https://kirillzyusko.github.io/react-native-keyboard-controller/docs/api/components/keyboard-sticky-view)) — `KeyboardStickyView` for the composer riding the keyboard's exact curve on the UI thread; `useReanimatedKeyboardAnimation().progress` for anything else that must move in lockstep.
- **Streaming markdown: [react-native-enriched-markdown](https://github.com/software-mansion-labs/react-native-enriched-markdown)** (Software Mansion) — native md4c parse + native text render with `streamingAnimation`, so token-by-token painting never touches the JS thread. Constraint ours, not theirs: the **learner** surface renders a constrained markdown subset on the doc-08 reading ramp (no arbitrary tables/links for K-2); parent/tutor surfaces get the full flavor.
- **Sheets: [react-native-true-sheet](https://sheet.lodev09.com/)** — real native detents for S27 ("what Natalie remembers"), the reasoning-style "how I got this hint" trace, and safety-alert detail.
- **Composer chrome: [`@callstack/liquid-glass`](https://github.com/callstack/liquid-glass)** with the `isLiquidGlassSupported` fallback branch — and note the pleasant convergence: our own doc-02 policy already says *system chrome may be glass, canvas never*. The composer is chrome; the lesson canvas stays paper.
- **"Thinking" state:** the Skia clock-driven shimmer pattern, re-skinned to Schoolhouse (ink text, yellow highlight band), `prefers-reduced-motion` → static label. Copy is "Natalie is thinking" tier-appropriate per band.
- **Motion:** Reanimated entering presets for bubbles (`SlideInDown` + hard-decel easing), delayed fade for the thinking row so the two read as one motion — exactly the demo's timing trick.
- **Transport stays SSE** (doc 12 decision, unchanged) — and here's why their WebSocket argument doesn't move us: their WS win is the *client↔provider tool loop* (only new items + `previous_response_id` per continuation). In our architecture **the tool loop runs inside the gateway** — retrieval tools are server-closed over identity (doc 11 §4) and never round-trip the client. The gateway may well use provider WS mode *internally* for exactly their ~40%-on-20-tool-calls reason; the client contract stays one screened SSE stream. Doc 12's revisit trigger (live co-presence → WS) stands.
- **Fetch layer: [react-native-nitro-fetch](https://github.com/margelo/react-native-nitro-fetch)** ([benchmarks](https://fetch.margelo.com/docs/benchmarks)) under our typed fetch client (doc 11 §2) — their release-build benchmark: ~1.30× average over built-in fetch. One dependency, every API call faster. Evaluate `prewarmOnAppStart` ([nitro-websockets](https://fetch.margelo.com/) family; ~150ms iOS / ~250ms Android measured) for the session-bootstrap call.

## 2. Speech — the genuinely new unlock (Phase 2)
- **STT on-device, adopt:** [`@react-native-ai/apple` Transcription](https://www.react-native-ai.dev/docs/apple/transcription) (SpeechAnalyzer) on iOS — **the child's raw audio never leaves the device**; the transcript enters the Safety Plane exactly like typed input (L1–L4 before any model, L5 on the stream back). Android path: evaluate ADK/ML Kit equivalents at the implementation PR; until parity, Android voice input can ship server-STT *with* the doc-07 no-training/retention rules, or wait — ADR at PR time.
- **TTS, staged:** v1 Natalie speaks via on-device AVSpeechSynthesizer ([`@react-native-ai/apple` Speech](https://www.react-native-ai.dev/docs/apple/speech)) — free, offline, instant. The **premium Natalie voice** (consistent character voice, phoneme timing for the embodied avatar's mouth) is a server-TTS Phase-3 ADR. Flagged follow-up read: Margelo's companion post on a 3D AI assistant (Filament render, realtime voice, amplitude lip-sync) is the closest published prior art to embodied Natalie — study it before the avatar build.
- **Consent + indicator rules (binding):** microphone use is guardian-consented per doc 06, a visible recording indicator is always on when the mic is open, and raw audio is never persisted — transcript only, under the doc-07 retention schedule.

## 3. On-device embeddings & local RAG — allowed, narrowly (Phase 3, ADR'd)
Callstack's stack (Apple NLContextualEmbedding; llama.rn embeddings + reranking) + the sqlite-vec local-RAG pattern from Margelo's "RAG in your pocket" post enable **retrieval-only** features with zero egress: a tutor searching their own session notes offline; a parent searching their family's summaries. Generation stays out; search of *your own already-authorized data* comes in. Loop-B posture actually improves: local retrieval means those queries never even reach us.

## 4. Explicitly evaluated and parked
- **On-device generation for adult ops drafting** (Apple FM / Gemini Nano): permitted *in principle* (no egress at all), parked for consistency and quality — one Natalie brain, one audit trail. Revisit if offline ops drafting becomes a real demand signal.
- **`@react-native-ai/json-ui` generative UI:** watched, not adopted. Children's surfaces are deterministic UI only — a model composing UI for a child fails doc 07's review bar in v1. Possible future for *tutor-side* widget drafting.
- **MLC engine:** their own docs mark it experimental — not production. Matches our catalog discipline; ignored until stable.

## 5. Performance discipline (adopted as our bar, with their measured numbers as targets)
Their release-build measurements on iPhone 16 become Moyo's chat budget: **57–60fps on both threads while scrolling a long conversation (~15% CPU / ~225MB); UI thread holds 60fps during generation; ~0.6s cold start to first frame.** Enforcement: profile **release builds only** with [react-native-release-profiler](https://github.com/margelo/react-native-release-profiler) + [react-native-performance-toolkit](https://github.com/Nodonisko/react-native-performance-toolkit); the AI SDK Profiler DevTools (OTel spans, runtime-agnostic) in development; these land in the doc-09 per-screen verify loop for every chat-adjacent PR.
**Plus one security bonus for doc 11 §6:** **[rnsec](https://www.rnsec.dev/)** scans the app binary in CI for shipped secrets — mechanically enforcing "no provider key ever reaches a bundle," which until now was only a lint rule on `server-only`.

## 6. Dependency & compat notes (anti-slop)
All Nitro-family packages assume the New Architecture and native builds (Expo prebuild / dev client — no Expo Go), which the starter already satisfies; exact package versions, API names, and Expo SDK 57 compatibility are verified **at the adoption PR against installed source** per the standing no-invented-APIs rule — this doc commits to the architecture, not to memorized signatures. Every new package enters through the pnpm catalog (single-version rule, doc 03).
