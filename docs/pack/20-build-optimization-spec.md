# Build & Size Optimization — small Android, iOS, and web builds, driven by the shops' own skills
**Doc 20 · Moyo platform pack · Date:** Aug 21, 2026
**Scope:** (A) wire Callstack's and Margelo's agent skills into the repo so every agent session optimizes from their playbooks, not vibes; (B) per-platform size budgets with CI ratchets; (C) adopt `react-native-runtimes` for the one surface that earns it. Constraint carried forward from doc 18: **zero model weights in the app binary** — the capability manager downloads everything; nothing here relaxes that.

---

## Part B — Size discipline per platform, enforced by ratchet
**Budgets are starting lines, the ratchet is the law:** CI fails any PR that grows a platform's install/first-load size beyond threshold without an explicit, reviewed override. Baselines set at PR-59; starting targets — Android ≤ 25 MB download (per-device, post-split), iOS ≤ 35 MB App Store download, web ≤ 170 KB gzipped first-load JS on marketing routes and a budgeted app-shell per authed route. Honest numbers for a New-Arch Hermes app with a 3D avatar kept *out* of the binary; tightened as baselines prove better.
- **Android:** AAB with Play's automatic per-ABI/density/language splits; R8 with resource shrinking on release (keep-rules for RN/Nitro/ExecuTorch audited via the skill's R8 reference); `reactNativeArchitectures` trimmed for release (arm64-v8a + armeabi-v7a; no x86 in production); Hermes bytecode (default); drawables as WebP/AVIF; the ExecuTorch runtime `.so` ships, its **models never do** (doc 18).
- **iOS:** asset catalogs so app thinning works; strip symbols and upload dSYMs to Sentry rather than shipping them; dead-code stripping on; static-linkage audit to avoid duplicated frameworks; image assets through the catalog pipeline; ExecuTorch/CoreML framework weight measured in the baseline.
- **Shared JS (both apps):** [Expo Atlas](https://github.com/expo/expo-atlas) is the bundle x-ray — snapshot artifact in CI weekly and on demand; Metro inline-requires + lazy `require` for heavy features; **barrel discipline** — Metro does not tree-shake, so the doc-10 typed barrels stay *thin* (types and tokens erase at compile; the rule is **no runtime re-exports of heavy modules through barrels** — feature code imports entrypoints directly); library audit per the skill (dedicated RN SDKs over web polyfills); font subsetting for Archivo Black / Space Grotesk / Spline Sans Mono to the doc-16 locale charsets; images via expo-image with WebP/AVIF sources; **every Natalie 3D/avatar asset lives on the CDN behind the capability manager's cache — never in the bundle.**
- **Web (Next 16):** RSC keeps client JS down by default — the enforcement is a **`"use client"` boundary audit** (client components stay leaf-shaped; the doc-17 pending-changes provider is the pattern: state at the leaf, server components above); heavy islands (the web Natalie embed, charts) load via `dynamic()` with suspense; `next/font` subsetting; `next/image` AVIF; per-route first-load budgets checked against `next build` output in CI.
- **Monorepo:** `pnpm dedupe --check` in CI; `sideEffects: false` on shared packages where safe (web bundlers tree-shake, Metro doesn't — both sides benefit differently); the doc-10 platform-fork pattern (`.native.tsx`) is also the size mechanism keeping native deps out of the web graph.

## Part C — `react-native-runtimes`: adopt for the surface that earns it
[margelo/react-native-runtimes](https://github.com/margelo/react-native-runtimes) (Margelo × Callstack, MIT, docs at [runtimes.margelo.com](https://runtimes.margelo.com/)) runs selected components in **isolated Hermes runtimes** so heavy surfaces stop competing with navigation, gestures, and input on the main VM. Requirements all match the stack: RN 0.76+, New Architecture required, Hermes, nitro-modules, Expo config plugin included. Their own guidance says reach for it when *one or two expensive features monopolize the main runtime* — so we adopt narrowly:
- **`natalie-runtime`** — the tutoring session surface (streaming markdown + LegendList) mounts via `OnRuntime`/`ThreadedScreen`, so token streaming never contends with nav or input; this buys structural headroom for the doc-15 budget (57–60 fps on both threads *while streaming*). **Prewarm** (`ThreadedRuntime.prewarm`) when Today's Path shows the session card — their prewarm-before-navigation pattern, applied to the one screen a child is about to tap.
- **Headless task:** learner-brief/edu-store hydration runs on a worker runtime before the session mounts (their `registerThreadedHeadlessTask` pattern) — the session opens against a warm store.
- **`@react-native-runtimes/state`** only where state genuinely crosses runtimes (session status, streaming flags) — and per their own rule, **pass ids, not large objects**; transcript content stays in the runtime that renders it.
- **Adoption posture:** the library is young (0.x) — behind a feature flag, verified with the doc-15 release-build profiling discipline before default-on; each extra runtime costs memory, so it's the chat surface first, the 3D avatar route as the *only* candidate second, and nothing else without profiler evidence.
