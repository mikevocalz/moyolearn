# Gauntlet Loop & the Bun 1.4 Migration — quality loops for taste, a check-gauntlet for the toolchain
**Doc 21 · Moyo platform pack · Date:** Aug 21, 2026
**Two asks, two verdicts:** (A) `gauntlet-loop` — adopt it, for the surfaces it's actually built for; (B) convert the monorepo pnpm → Bun 1.4 — yes, phased, with one non-negotiable gate at the front.

---

## Part A — Gauntlet Loop: adopt for taste surfaces, not for migrations
**What it is:** [robonuggets/gauntlet-loop](https://github.com/robonuggets/gauntlet-loop) packages [Matt Shumer's](https://github.com/mshumer) gauntlet-loop technique (from [Claude of Duty](https://github.com/mshumer/Claude-of-Duty), [original prompt](https://github.com/mshumer/Claude-of-Duty/blob/main/prompt.md)) as a single Claude Code skill (CC BY 4.0): give a goal → it proposes 2–3 **quality bars** that must be *named, fetchable, comparable* (a specific live page/post/repo, never "award-winning") → it emits one ~150-word prompt → a fresh session splits the work into builder + **separate harsh-critic** pairs → the critic does a **blind side-by-side against the bar and picks a winner** (a pick, not a score that drifts) → the loop exits only when our work wins. It's the evaluator pattern from [Anthropic's building-effective-agents](https://www.anthropic.com/engineering/building-effective-agents), weaponized. Guide Mike shared: [thepromptindex.com walkthrough](https://thepromptindex.com/ai-loop-engineering-gauntlet-loop-guide.html).
**Where it helps Moyo — surfaces where "good enough" is the enemy and a bar is fetchable:**
- **Learner screens** (S01 Today's Path, session surface): bar = a named, screenshotable reference screen from a best-in-class kids' learning product — judged blind on which one a 7-year-old parses faster. One Moyo-specific rule the skill doesn't have: **bars for learner surfaces must also pass our own constraints** (doc-08 bands, doc-07 posture) — the critic judges craft *within* our rules, never imports an adult product's dark patterns because they "won."
- **Marketing/landing page** vs a named live campaign page, desktop + mobile screenshots.
- **The district board pack** (doc 19) vs a named published district report — judged on which one a superintendent could present cold.
- **Brand/board artwork** vs a named identity case-study page.
- **Docs themselves** (this pack's public-facing successors) vs a named great spec.
**Where it does *not* fit — the Bun migration.** By the skill's own rules the bar must be named/fetchable/comparable, and its top documented failure mode is a vague bar making the critic hallucinate approval. A package-manager migration has no bar to screenshot — success is binary and mechanical. The right loop there is the *deterministic* cousin: **CI is the critic, the checklist is the gauntlet, loop until green** (Part B §4). Same looping spirit, honest judge.
**Install (extends PR-58's skills wiring):** `cp -r gauntlet-loop/.claude/skills/gauntlet-loop <repo>/.claude/skills/` — it sits beside the Callstack/Margelo skills; invoked as `/gauntlet-loop <goal>`.

## Part B — pnpm → Bun 1.4, phased, gate-first
**What's verified about Bun's monorepo story:** [catalogs since v1.2.14](https://bun.com/blog/bun-v1.2.14) (`catalog:` protocol, versions defined once under `workspaces.catalog` in root package.json — our pnpm catalog pattern ports); [isolated installs](https://bun.com/docs/pm/isolated-installs) give pnpm-style strictness (central `node_modules/.bun` store + symlinks, phantom-dependency prevention, default for new workspace projects); [`bun install --filter`](https://bun.com/docs/pm/cli/install) for workspace-scoped installs; overrides/resolutions supported; [1.2.19 added `bun why`, `bun pm pkg`, and honored `.npmrc` `save-exact`/`link-workspace-packages`](https://socket.dev/blog/bun-1-2-19-adds-isolated-installs-for-better-monorepo-support).
**GATE ZERO — the go/no-go, before any conversion work:** [oven-sh/bun#23615](https://github.com/oven-sh/bun/issues/23615) reported (Bun 1.3.0) that **isolated installs + catalogs together failed to deduplicate compatible semver ranges and left stale cache entries — "unusable for production monorepos," with the only workaround being the hoisted linker.** Falling back to hoisted is *not acceptable here* — hoisting surrenders exactly the phantom-dep strictness that pnpm gives us today. So the spike (PR-64) pins the exact Bun 1.4.x version, reproduces that issue's scenario against *our* catalog, and the migration proceeds only if dedup behaves. If it doesn't: we stay on pnpm and re-test next Bun release. No pride in the tool choice — pride in the discipline.
**The phases (each lands green before the next):**
- **Phase 0 · Spike (PR-64):** branch; pin Bun version (version file + CI pin — exact pinning mechanism confirmed at the spike, not invented here); port `pnpm-workspace.yaml` catalog → `workspaces.catalog` (note at spike: pnpm's *named* catalogs vs Bun's catalog shape — flatten if needed); `bun install --linker isolated`; commit `bun.lock`; build the **`trustedDependencies` allowlist** — Bun blocks lifecycle scripts by default, which matches our doc-07 minimal-postinstall posture, and Expo/RN native deps that legitimately need scripts get explicit entries; gate-zero report.
- **Phase 1 · Scripts + tests (PR-65/66):** workspace scripts through `bun run` with `--filter`; **`bun test` adopted for pure-TS packages first** — the registry, types, i18n catalogs, and the doc-17 change-reducers are pure functions and ideal targets; Metro and Next dev servers stay on their default Node runtimes for now (Bun is the package manager and script/test runner in this phase, not the app runtime).
- **Phase 2 · CI + cloud (PR-65):** setup-bun in Actions with `bun.lock` caching; EAS build config pinned to the same Bun version (exact `eas.json` field verified at the PR); Vercel installs with Bun while **Next/Payload production runtime stays Node** — flipping prod runtimes is a separate future ADR with its own gauntlet, not a rider on a package-manager change.
- **Phase 3 · Cleanup:** `pnpm-lock.yaml` and pnpm references removed only after a green week; docs 03/12 get a one-line Bun addendum pointer (history stays honest); CLAUDE.md command examples updated.
**§4 The migration gauntlet (CI is the critic — every phase loops until all pass):** fresh `bun install --linker isolated` from cold cache · `bun why` spot-checks show no phantom resolution paths · typecheck across all workspaces · `next build` clean · Expo prebuild + EAS dry-run builds for both platforms · full `bun test` suite · dev-server smoke on all three apps · **doc-20 size ratchet unchanged** (a package-manager swap that moves app size means something resolved differently — investigate, don't accept) · lockfile diff reviewed for silent major bumps.
**Rollback:** the branch is the rollback; pnpm lockfile survives until Phase 3; any gauntlet failure past merge reverts the toolchain commit, not the feature work on top.
