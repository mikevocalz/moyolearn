## 2026-09-26 addendum — production redeployed; second native sign-in bug fixed on main (device pass pending)

- **A production deploy newer than `719e2be` exists.** Vercel deployment
  `dpl_H3T16yXzCbG2RAcv1bu4WnWsh5m6` on app.moyolearn.com carries `main`
  commit `3c628fa` ("Trust the native moyo:// origin so mobile sign-in stops
  failing"), which adds `trustedOrigins: ['moyo://']` to
  `packages/auth/src/server.ts`. The `@better-auth/expo` client sends
  `expo-origin: moyo://` that the server plugin copies into `Origin`; with
  `trustedOrigins` empty every native sign-in failed `INVALID_ORIGIN`
  (surfaced as "Invalid callbackURL"). Curl-verified post-deploy:
  `expo-origin` now reaches the credential check. **Caveat:** `3c628fa`
  predates merge `f428379` and does **not** contain the SDK 58 line — so this
  deploy still does not ship the #69/#70 fixes below. Whether the
  reset-mail/ward-pagination fixes shipped in this or an earlier deploy is
  not verified by this audit — check before assuming the "Not done" list
  above is cleared.
- **A second native sign-in defect was found on device — fix now landed on
  `main`.** The email sign-in response carries `redirect: true`, so the expo
  client lazily imports `expo-web-browser` — not installed — and red-boxes
  `Requiring unknown module`. `3c310e7` committed the fix as
  `expo-web-browser: 57.0.3` on the pre-merge main (58.x demands compileSdk
  37 while that workspace's Expo was 57.0.15); merge `f428379` then brought
  the Expo 58 preview catalog to `main`, and the shipped pin is now
  `expo-web-browser: ~58.0.2` in `pnpm-workspace.yaml` + `catalog:` in
  `apps/mobile/package.json`. Needs a rebuilt APK and an on-device sign-in
  pass before it is verified — merged-main evidence
  (`docs/handoffs/evidence/xr-layout-probe/quest-3s-merged-main.png`/`.log`)
  was **pending capture** at this audit.
