## How a set is made

1. `pickPracticeTags` reads the submission's questions in `orderIndex` order. A recorded misconception tag maps through `MISCONCEPTIONS[tag].skillId` (packages/student-model/src/facts.ts) and ranks first. A question whose outcome is `supported-with-hints` or `unresolved` gets its confirmed text classified by `practiceTagForText`. `attempted`, `skipped` and `solved-independently` add nothing. The result is deduplicated and capped at 3.
2. `buildPracticeDraft` seeds the generator with the new `practiceSetId`, asks for 8 items, runs `verifyPracticeItems`, and keeps only what verified. If no tag came out, `targetedTags` stays empty, the generator draws on the band's defaults, and the preview says "general practice for the grade band". It does not imply targeting it did not do.
3. The service reports dropped items through `reportDropped` with id, skill tag and checker reason. The route logs that as JSON with no prompt text.

The seed is the row id, so an approved set regenerates byte-for-byte from `(practiceSetId, targetedTags, band)`. The test asserts determinism.

## Refusals kept

- No grading. Nothing reads a child's answer. The tags come from tutoring outcomes, not from marking. Approving only says the adult read the set.
- The key is guardian-only. `canHoldPracticeKey` refuses any `isLearner` caller, refuses a caller whose id is the learner's own, and refuses a guardian whose ward list (`loadGuardianWards`, active guardianships only) lacks the learner. All three service entries re-read wards, so revoking a guardianship also revokes approve and print on sets made before the revocation.
- A draft does not print: `practiceSetForPrint` throws `PracticeSetNotApproved` and the route answers `409 { error: 'not-approved' }`. The preview only shows the print buttons after approval.
- The sheet carries no answers, no score box and no right/wrong column. The test asserts that `Answer:` never appears in sheet mode. Labels are in words ("Practice sheet (not a test)", "Answer key — for the adult"). The Draft/Approved badge has text as well as a tone, so colour carries no meaning on its own.
- The print route uses the report print route's six headers verbatim, including the CSP.

## Checker coverage, stated plainly

The checker proves one thing: substituting the printed answer into the printed prompt gives the same exact rational on both sides (`checkExactMath`, Compute Engine 0.128.12). It reads the printed prompt, not a value handed over by the generator.

It cannot verify, and the generator therefore does not emit:
- percent, units, money, time, or anything with words in the expression
- powers, roots, absolute value, inequalities, comparisons ("which is larger")
- simplify/expand/factor tasks, where the answer is a form rather than a value
- more than one unknown, systems, quadratics
- word problems of any kind

It also does not prove:
- **Uniqueness of a root.** A value that satisfies the equation passes. The linear templates have exactly one root by construction, but that is a property of the generator and no test proves it in general.
- **Form.** `2/4` and `1/2` are both "equivalent". The key prints the generator's reduced form and tells the adult that equivalent forms are right.
- **Fit.** Whether an item suits the child, the band or the misconception is not something the checker knows. The guardian's approval is the only fit check, and the preview exists for that reason.

`practiceTagForText` is a shape heuristic, not a parser. On word problems and percent it returns null rather than guessing a neighbouring skill. A mis-OCR'd question that still parses as arithmetic would be classified by its wrong text. Because approval happens on the confirmed revision text, that risk falls to whoever confirmed the transcription.

## Native path

`practice-print.native.ts` calls `printToFileAsync({ html, width: 612, height: 792 })`, then `shareAsync(uri, { mimeType: 'application/pdf', UTI: 'com.adobe.pdf' })`, and returns `'unavailable'` when `isAvailableAsync()` is false. The HTML is rendered on device from the set the screen already holds, so the key never travels as a URL. Both are Expo modules from the SDK 58 bundle, so no Nitro module or custom native target is needed. Running it on a device needs a dev-client rebuild because the native modules are new. Not built or run on a device in this session.

`practice-print.web.ts` opens the print route in a new tab. It deliberately omits `noopener`, because with it `window.open` returns null on success and a blocked pop-up would look the same as an opened tab.
