## Decisions

- Outcome to status follows contract §Report: `solved-independently` maps to `solved-independently`, `supported-with-hints` to `solved-with-help`, and everything else to `still-working`. `childAnswer` is null and `submittedIncorrect` is false on every worksheet row, because nothing recorded an answer.
- Facts are recounted from outcomes. `attempted` excludes `unattempted` and `skipped`. Duration stays the session's.
- No transcript reaches the narrative. `narrativeEvidence` sets `problem: ''`, because a homework session's `problem` is a copy of the current question's text. Revision text sits only in `questionRef.text`, and `narrativePayload` does not serialize `questionRef`. The numbers a narrative can quote therefore no longer include digits from the question.
- Block 6 for a worksheet session comes from `homeworkNextStep`. Its inputs are misconception tags (lowercase words only, at most two, taken from questions not finished without hints) and outcome counts. The sentence states no number. Each candidate sentence goes through `lintNarrative`, and the tag-free sentence is the fallback.
- When no graded turn produced a skill, which is the normal case for a photographed page since `evaluationReady` is false, block 1 states the worksheet counts. Without that, the deterministic headline would say "no graded problems" above a full worksheet.
- Print outcome words are "Finished without hints", "Finished with hints", "Attempted, still open", "Still working", "Skipped" and "Not started". I avoided "solved" and "correct" because nothing graded the page.

## WCAG 2.1 AA notes for the print sheet

| Criterion | Status |
| --- | --- |
| 1.3.1 Info and relationships | Worksheet rows are a `<table>` with `<caption>`, `<th scope="col">` headers and `<th scope="row">` order cells. A screen reader announces "Order 2, Outcome, Attempted, still open". |
| 1.4.1 Use of colour | Outcome is printed as words. No status uses colour, so the sheet reads the same in grayscale. The table uses borders, not fills. |
| 1.4.3 Contrast | #201e1b on #fff 16.63:1. #625b50 (meta, eyebrow) on #fff 6.71:1. #4a443b (caption, header line) on #fff 9.63:1. #201e1b on #f6f3ee 15.02:1. All computed in this session. |
| 1.4.11 Non-text contrast | Table rules #8a8378 on #fff 3.75:1. Button border #5c564c on #fff 7.27:1. |
| 2.4.7 Focus visible | Button has `:focus-visible` with a 3px #201e1b outline. |
| 2.5.5 Target size | Button `min-height:44px`. Width exceeds 44px by its label. |
| 1.4.4 / 1.4.10 Resize and reflow | Not verified. Body is max-width 760px with no fixed widths. A six-column table at 320px CSS width will scroll horizontally, which is a 1.4.10 risk for the on-screen view only. Not verified in a browser. |
| Print | `@page` letter, 0.7in margins, 12pt body. `thead{display:table-header-group}` repeats headers on each page. `tr`, `.question` and `.note` avoid breaks inside. `h1`/`h2` avoid breaks after. `orphans:3;widows:3`. The screen header and button are hidden in print. |

The header text is exactly "Print or save as PDF from your browser". It sits in a `<header>` beside the existing button and is hidden in print.
