## Defects found in the partial work, and the fixes

1. **The panel claimed `aria-modal` and enforced none of it.** On medium widths and up it was an absolutely positioned `View`. Tab left it on web, VoiceOver could reach the feed behind it, and the click-away layer used `fixed inset-0`, which has no meaning on native. It is now a transparent react-native `Modal`, placed from the trigger's `measureInWindow` box the way `packages/ui/Menu.native.tsx:Menu` places itself. On web, react-native-web's `ModalFocusTrap` brackets focus, `ModalContent` turns Escape into `onRequestClose`, and focus goes back to the trigger on unmount. I read these in `node_modules/react-native-web/dist/exports/Modal/`. On native the Modal is its own window, and the panel also sets `accessibilityViewIsModal`. The hand-written `document` keydown listener is gone.
2. **"No child linked yet" showed while the wards read was still loading.** On a cold load the timeline got `learnerAuthId === undefined`, and for a second or two it told a parent their child was not linked. The timeline now reads the wards query from the shared cache (same key, so no second request): a skeleton while it loads, nothing on failure (the header already shows that), and the sentence only after the read answers with zero wards.
3. **Broken list semantics.** One `role="list"` wrapped `Section`s that held the `listitem`s, so on web ARIA no list owned the items. Each date group is now its own list, labelled "<Name>'s homework, <date heading>", and sits under its heading.
4. **A copy claim with no source.** The sheet said "<child> starts question one with Natalie on their own device." Nothing in the flow requires a second device (`docs/design/homework-end-to-end-2026.md` describes cross-device resume, not a device rule). Cut to "Then <child> starts question one with Natalie."
5. **Duplicated wards states.** Home and `/homework` each had their own skeleton/failure/switcher block, and the route called `readFailureCopy` twice and spread its `signedOut` flag into `ReadFailure`. Both now mount `GuardianFamilyHeader`.

Also: the em dashes in user-facing failure copy became full stops, and the duplicate "Homework" label inside the no-child card was removed (the home section label and the route's `Heading` already name it).

## Handoff spec

**Layout.** Guardian home: what's-next card, then `GuardianFamilyHeader` (switcher row, then the assign trigger), then the "Homework" label and the newest three worksheets, then `ParentHomeContent`. `/homework`: an H1 "Homework", the same header, then the full timeline. `Container width="detail"` on both.

**Tokens.**

| Slot | Token |
| --- | --- |
| Header block gap | `gap-group` (1.5rem cool) |
| Switcher to trigger | `gap-stack` (0.75rem) |
| Between chips | `gap-element` (0.5rem) |
| Date heading | `text-label uppercase tracking-wide text-text-muted` |
| Row card | kit `Card`, `gap-element` |
| Subject | `Text variant="label" tone="muted"` |
| Title | `text-base font-semibold text-text`, 2 lines max |
| Count | `Text variant="data" tone="muted"` |
| Outcome numeral | `font-mono text-data` |
| Panel | `rounded-card border-2 border-border bg-surface-raised p-inset shadow-card`, 352dp wide, `maxWidth` window minus 32 |

There is no role accent anywhere in these surfaces. `check-role-accent.mjs` passes.

**Props.**
- `GuardianFamilyHeader { child: ChildSummary | undefined }`
- `GuardianAssignSheet { child: ChildSummary | undefined }`: renders nothing without a child
- `GuardianHomeworkTimeline { learnerAuthId?, childName?, limit?, onSeeAll?, onUpload? }`

**States.** Wards: loading (one-line skeleton), failed with no earlier list (`ReadFailure` with retry, plus Sign in on 401), answered (switcher, hidden below two wards). Timeline: wards loading (card skeleton), wards failed (nothing; the header speaks), no ward, loading (two card skeletons), failed with no cached rows (`ReadFailure`), empty (`EmptyState` with the upload action), rows (grouped by date, "All homework" when `limit` cut the list). `keepPreviousData` keeps the last good list through a failed refetch, so failure only replaces content when there is none.

**Size classes.** Compact (<600dp): the trigger opens the kit `BottomSheet` (snap points 55% and 85%, never full screen). Medium (600–839dp) and expanded (840dp+): the trigger opens the anchored panel below the trigger. It flips above when 300dp will not fit below, and it is clamped 16dp inside the window. `useWindowSizeClass` re-renders on rotation, fold and split-screen. A sheet left open across an unfold stays open and renders as the panel. A panel left open across a fold to compact becomes the sheet without a fresh measurement.

**Fold posture.** Not handled. On a vertical hinge the panel, placed from the trigger's left edge, can straddle the fold. `packages/ui/adaptive-panes` has `useFoldLayouts`, and the panel does not read it yet. Open question in `homework-assign-sheet.md`.

**Edge cases.**
- One ward: no switcher; the trigger and timeline still name the child.
- Zero wards: no switcher, no trigger, "No child linked yet".
- A revoked guardianship drops the child on the next wards answer. `setChildren` runs only on an answered read, so an outage keeps the last selection.
- A malformed `localDate` keeps its row under its raw string.
- A sheet done on the 14th in Denver shows as the 14th in New York, because `parseLocalDate` builds a local wall-clock date.
- The ward for `/upload` comes from `family.store` (`useActiveLearnerId()`, read by B2's CaptureScreen), never from a URL param.
- `/api/guardian/wards` and `/api/homework/submissions` accept a bare array (the contract) or a `{ wards }` / `{ submissions }` envelope.

**Motion.** Home's header sits inside the existing `FadeIn`. The panel fades in through `Modal animationType="fade"`. The sheet uses the platform sheet animation. There is no motion on the chips beyond the kit `PressScale`.
