## Emotion presets — the values that conflict

`EMOTION_PRESETS`, `packages/avatar/src/emotion.ts`. BEAT's eight categories as ARKit baselines.

| Preset | Channel | Value | Conflict |
|---|---|---|---|
| `happiness` | `mouthSmileLeft/Right` | 0.55 | Beats every viseme corner below it under `max()` — the permanent smile |
| `surprise` | `jawOpen` | 0.15 | Becomes a floor the mouth cannot close below |
| `sadness` | `eyeBlinkLeft/Right` | 0.15 | Writes a channel `blink` owns; reads as a stuck half-shut lid |
| `surprise`, `fear` | `eyesWide` | 0.6 / 0.7 | Not one of the asset's 52 morph targets — see below |

`EmotionState` eases transitions over `TRANSITION_S = 0.4` with a smoothstep (`packages/avatar/src/emotion.ts`). Keep that; an instant baseline change reads as a glitch on a face.

## The `eyesWide` name

| Site | File:line |
|---|---|
| Written by presets | `packages/avatar/src/emotion.ts:70,75` |
| In `IDLE_CHANNELS` and `IdleFrame` | `packages/avatar/src/idle/engine.ts:65,228` |
| Anticipation envelope | `packages/avatar/src/idle/engine.ts:480-489`, `idleConfig.anticipation.eyesWide = 0.15` |
| Merged by the 2D bus | `packages/avatar/src/face-bus.ts:144` |
| Translated by the 3D writer | `packages/avatar/src/presence/humano.ts:751-752` → `eyeWideLeft`, `eyeWideRight` |

`eyesWide` is **not** in the assets' 52 morph targets (`packages/avatar/rig-manifest.json`). The 3D path translates it; the 2D path hands it to `encoder.encode()`, where `directEncoder` drops unknown names. Whether that costs the anticipation beat its eye-widen depends on the container in use — check `arkit-map.json` or the rebaked container's `expressionNames` before assuming.
